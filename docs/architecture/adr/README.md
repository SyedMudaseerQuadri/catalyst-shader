# Catalyst Architecture Decision Records

Use ADRs for decisions that materially affect renderer architecture, resource contracts, temporal behavior, performance strategy, compatibility, or long-term maintainability.

## Naming

Use:

a new ADR file named `ADR-NNN-short-description.md` in this directory

## Required Structure

Each ADR should contain:

1. Status
2. Context
3. Problem
4. Options considered
5. Decision
6. Technical rationale
7. Quality impact
8. Performance impact
9. Compatibility impact
10. Migration/implementation plan
11. Validation evidence
12. Consequences
13. Revisit conditions

## Status Values

- PROPOSED
- ACCEPTED
- SUPERSEDED
- REJECTED
- DEFERRED

Do not rewrite historical decisions to make them appear correct in hindsight. Supersede them with a new ADR when evidence changes.
